# 软著材料整理说明

## 1. 当前可用的软件资产

项目已经具备可独立运行的V1.0软件、两版RISC-V示例固件、测试、架构说明和操作说明。源码由Python、JavaScript、CSS、HTML、C和汇编组成，核心实现没有复制第三方源码，也没有把生成的ELF、MAP、缓存或依赖包计入源码规模。

后续生成软著代码材料时，应从真实源码中抽取连续内容，并按申请系统当时的页数、每页行数和前后连续页要求排版。不要把测试输出、压缩数据、构建产物或同一文件的重复副本作为源码材料。

## 2. 建议登记名称

- 软件全称：RISC-V嵌入式固件资源画像与版本差异分析软件
- 软件简称：RVFPA
- 版本号：V1.0

名称已经统一写入`rvfpa/constants.py`和界面。正式申请前如果改名，应同步修改代码、README、操作手册和申请表，避免材料间名称不一致。

## 3. 需要申请人确认的信息

以下内容不能仅凭仓库判断，正式生成申请材料前必须由申请人确认：

- 著作权人姓名或单位全称、证件类型和证件号码。
- 开发方式是独立开发、合作开发、委托开发还是下达任务开发。
- 开发完成日期和是否已经发表。
- 已发表时的首次发表日期、地点和方式。
- 权利取得方式及权利范围。
- 软件运行所需硬件、操作系统、开发工具和目标用户的最终表述。
- 是否存在雇佣关系、实验室任务、项目经费或第三方合同导致的职务成果风险。

## 4. 权属风险控制

- 保留项目创建和持续开发记录，包括文件时间、版本历史、测试记录和设计文档。
- 不导入单位、课题组或他人项目中的专有源码，除非权属文件明确允许。
- 示例固件仅用于展示分析能力，不应替代核心软件源码成为主要材料。
- GNU工具链只是软件调用的外部工具，不将其源码或二进制纳入申请代码。
- 若未来引入第三方库，应保留许可证，并在申请材料中排除第三方源码。
- 正式提交前检查代码中的作者名、单位名、旧项目名和不一致版本号。

## 5. 建议的软件功能描述

本软件面向RISC-V嵌入式固件研发与版本交付场景，对ELF固件、GNU链接MAP文件和链接脚本进行静态解析，形成文件身份、内存区域、节区、符号、指令扩展、函数、字符串、段熵和发布检查等资源画像；支持保存多版本分析快照，对代码体积、运行时内存、段、符号、区域、指令和扩展变化进行差异分析，并可按照用户配置的发布策略执行准入检查和导出HTML、JSON、CSV报告。

该描述是基于当前实现整理的草案。正式申请说明书应以最终冻结的软件版本和实际界面为准。

## 6. 版本冻结建议

正式整理材料前执行以下步骤：

1. 确认申请名称、著作权人和权属依据。
2. 冻结一个V1.0源码副本，不再混入V1.1功能。
3. 在干净环境重新构建示例并运行全部测试。
4. 启动Web界面，逐页截图并记录操作步骤。
5. 统计可提交的原创源码文件和行数。
6. 生成代码文档、操作手册和申请表信息草稿。
7. 人工核对名称、版本、日期、页码、截图和代码连续性。

当前目录是开发主目录，不应直接作为最终提交压缩包。最终材料应输出到独立目录，保留原始开发仓库不变。
